# 띄어쓰기 선택 규칙과 적용 범위

`engine/hangul_ime/spacing_policy.py`는 모델 결과 위에 사용자가 선택한 띄어쓰기 방식을 적용한다. ASCII 공백만 바꾸며, 보호 문자열과 탭·개행·연속 공백을 넘지 않는다. 기본 `compound=model`은 복합명사에 대한 추가 수정이 없다.

## 복합명사 붙임

연속된 명사라는 이유만으로 붙이지 않는다. 예전 규칙은 `학교 도서관 열람 시간 안내`를 전부 붙였으나, 현재는 이 명사구의 경계를 유지한다. 국립국어원은 단어별 띄어쓰기 원칙을 설명하며, 일반적인 명사 연결과 사전에 한 단어로 실린 표현을 구분한다. [제2항 설명](https://m.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&pageIndex=1&qna_seq=313129), [중간보고·최종 보고와 전문 용어 설명](https://m.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&qna_seq=309273).

`compound=join`은 다음을 모두 만족하는 범위만 붙인다.

- 문맥 분석에서 일반명사(`NNG`)로 분석된 연속 구간이다.
- 후보는 최대 4개 형태소·16자이며, 각 형태소 사이에 공백이 없거나 한 칸만 있다.
- 후보의 공백을 제거한 분석 결과가 동일한 표면형의 단일 `NNG`이다.
- 분석된 형태소 ID를 모델 사전에서 다시 조회했을 때도 표면형과 품사가 정확히 일치한다. 미등록어를 통째로 `NNG`로 처리한 결과는 근거로 쓰지 않는다.
- 긴 후보부터 선택하되 이미 선택한 구간을 겹쳐 연결하지 않는다. `A+B`와 `B+C`가 각각 단어라고 해서 `A+B+C`를 만들지 않는다.

예를 들어 `국어 사전 편찬 사업`은 `국어사전 편찬 사업`, `사과 나무 그림`은 `사과나무 그림`으로 바뀐다. `자료 처리 시스템`, `게임 개발 회사 직원`, `사과 배 포도 바나나`는 이 규칙만으로 붙이지 않는다. 고유명사(`NNP`)는 제외한다. 실제로 `친구엄마`는 모델에 작품명으로 들어 있어도 일반 문장의 `친구 엄마`를 붙이는 근거가 되지 않는다.

여기서 사전은 **Kiwi 모델의 어휘 사전**이며 표준국어대사전과 같지 않다. 모델의 어휘 등록은 모든 문맥에서 규범적으로 한 단어라는 보장이 아니다. 동음이의어 및 명사구와 복합어의 의미 차이까지 해결하는 규칙은 아니며, 모호한 경우 개인 사전의 분리형으로 덮어쓸 수 있다. 최대 길이를 넘거나 모델에 여러 형태소로만 등록된 복합어는 자동 붙임 대상에서 빠질 수 있다.

기술 근거는 [Kiwi 0.22.1 API 문서](https://bab2min.github.io/kiwipiepy/v0.22.1/kr/)의 `tokenize`, `Token.id`, `morpheme` 인터페이스다. 실행 시 네트워크 사전을 조회하거나 사용자 입력을 수집하지 않는다. 후보 조회 결과의 중복 계산만 한 번의 변환 호출 안에서 줄이며, 입력 문자열 캐시는 호출 사이에 유지하지 않는다.

## 다른 설정 및 개인 사전

`compound=separate`는 기존과 같이 분석된 명사 사이를 띄며, 이미 하나의 어휘 토큰인 `국제기구` 같은 단어를 임의로 쪼개지 않는다. `existing_spaces=preserve`는 모델의 변경으로부터 직접 넣은 공백을 보존하지만, 사용자가 명시적으로 선택한 붙임·분리 규칙과 개인 사전은 그 규칙이 맡은 경계를 변경할 수 있다.

고유명사와 전문 용어는 각각 `proper`, `technical` 설정 및 명시적 등록 표현에 따른다. 고유명사·전문 용어의 붙임 허용은 일반 명사 연쇄 전체에 대한 허용이 아니다. 전문 분야에서 한 개념으로 쓰이는 표현은 사전에 모두 실려 있지 않아도 전문 용어가 될 수 있다는 국립국어원의 설명을 고려해, 사용자가 확인한 표현을 등록할 수 있게 한다. [제49·50항](https://www.law.go.kr/LSW/admRulLinkProc.do?admRulNm=%ED%95%9C%EA%B8%80%EB%A7%9E%EC%B6%A4%EB%B2%95&chrClsCd=&mode=20), [전문 용어에 관한 국립국어원 설명](https://m.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&qna_seq=309273).

`BUILTIN_TERMS`는 기존의 소수 등록 예시이며 포괄적인 규범 사전이 아니다. 내장 표현보다 같은 표면형의 개인 등록 표현이 우선하고, 겹치는 등록 표현은 긴 표현이 우선한다. 개인 사전의 `compound` 항목을 등록하면 `자료 처리 시스템`처럼 모델이 여러 명사로 분석하는 표현도 명시적으로 붙일 수 있다. `custom` 항목은 개별 모드가 필수다.

## 검증

`engine/tests/test_compound_spacing.py`는 명사 열거·긴 명사구·고유명사 오인·미등록어·겹치는 결합·개인 사전 우선순위·레이아웃과 보호 문자열·반복 적용 안정성을 검증한다. `engine/tests/test_spacing_preferences.py`는 다른 띄어쓰기 선택과의 독립성을 함께 확인한다.

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=engine "$ENGINE_PYTHON" -m pytest -q -p no:cacheprovider \
  engine/tests/test_spacing_preferences.py engine/tests/test_compound_spacing.py
```
