# 매무시 0.5.2

2026-10-17

- Windows 판 추가(Windows 10 1809 이상 x64, ARM64 PC는 Windows 11). TSF 입력기로 64비트·32비트 앱 모두에서 동작한다. 설치 파일 하나(`Maimusi-0.5.2-Windows.exe`)에 x64·x86·ARM64X 입력기가 들어 있다. ARM64 판은 빌드와 실행 파일 형식만 확인했고 실제 ARM64 기기에서는 시험하지 않았다.
  - 설치 파일과 실행 파일은 코드 서명하지 않았다. 설치할 때 「Windows의 PC 보호」 창이 나오면 [추가 정보] › [실행].
  - 한/영 키로 한글·영문 전환, 작업 표시줄 입력 표시기(`가`/`A`) 클릭 전환, 한/영 키가 없는 키보드용 「오른쪽 Alt로도 한/영 전환」 설정.
  - 한자 키: 조합 중이면 변환, 변환 중이면 다음 후보.
  - 찰떡 엔진은 사용자당 한 프로세스를 모든 앱이 함께 쓴다(named pipe, 같은 사용자 확인). 쓰지 않으면 설정 시간 뒤 종료.
  - IMM32 앱(EDIT 컨트롤, `WM_IME_*`를 직접 처리하는 앱)에서는 입력 중인 문장을 커서 옆 창에 표시하고 확정할 때 넣는다.
  - Windows 11 스타일 후보·변환 창(밝게/어둡게, 강조색), 키캡 명령줄, Noto Sans KR 글꼴(동봉, OFL), 고해상도 대응 한/영 표시기, 카드형 설정 창, 설치 마법사 그림.
  - 입력 칸이 아닌 곳에서는 키를 가로채지 않아 한글 상태에서도 웹 페이지·동영상 단축키(YouTube F 등)가 동작한다.
  - 한/영 상태는 앱 사이에 즉시 공유되며, 앱이 스스로 바꾼 상태는 그 앱에만 적용된다.
  - Chrome·Edge·Electron 앱은 문서 안에서 바로 조합한다(IMM 연결 계층만 떠 있는 창 사용). 후보 창은 선택한 어절 아래에 뜬다.
  - 업데이트: 버전·빌드마다 별도 폴더에 설치하고, 열려 있는 앱이 쓰는 이전 폴더는 남긴다. TSF 프로필을 다시 등록하지 않아 열려 있는 앱의 입력기가 꺼지지 않는다. 배포 빌드 27.
  - 샌드박스 앱(시작 메뉴 검색창, 스토어 앱 등 AppContainer)에서도 이미 떠 있는 찰떡 엔진으로 띄어쓰기·후보를 쓴다. 엔진 파이프를 명시적 보안 설명자(소유자 사용자, 사용자·SYSTEM·AppContainer만 접근, 인스턴스 생성 권한 없음, 원격 거부, 중간 무결성 레이블)로 만들고, 입력기는 OpenProcess 대신 파이프의 소유자와 레이블로 서버를 확인한다(낮은 무결성 프로세스가 같은 이름으로 만든 파이프는 거부). 엔진은 샌드박스 클라이언트의 설정 변경·경계 학습 요청을 거부한다. 샌드박스 앱은 `%APPDATA%` 대신 `HKCU\Software\Maimusi\Sandbox`의 설정 사본(사용자 단어·학습한 경계 제외)을 읽는다.
  - 설정 프로그램, 설치·제거 프로그램. 게시자 표기는 세반시옷, 문의 admin@sebansios.com.
  - 설치 폴더에 `README.txt`(사용법, 국립국어원 「모두의 말뭉치」 출처 표기)와 `Licenses\`(사용권 계약, 제3자 고지, Noto Sans KR OFL, Kiwi LGPL 전문, Windows용 Python 런타임 라이선스와 그 안의 OpenSSL·libffi·Microsoft 재배포 런타임 고지). 사용권 계약과 고지문의 경로·LGPL 라이브러리 교체 방법을 Windows 판에 맞게 고쳤다.
- macOS 판(빌드 28): 앱 아이콘 바탕을 squircle(n=5 초타원, macOS 앱 아이콘 격자 824 pt)로 변경. 입력·엔진 동작은 0.5.1과 같고, 아래 공용 엔진·저장소 변경을 포함한다.
- 엔진: Windows에서 사용자 경계 보정 모델을 `%LOCALAPPDATA%\HangulSpacing\models\`에서 찾는다. stdin/stdout 프로토콜을 콘솔 코드 페이지와 관계없이 UTF-8로 고정.
- 저장소: 번들 데이터 파일의 줄 끝 변환 금지(`.gitattributes`). Windows checkout에서 해시 검사가 깨지던 문제 수정. 시험·도구의 파일 읽기·쓰기를 UTF-8로 명시.
- 개인정보 검사: Windows 홈 경로·컴퓨터 이름·UTF-16 문자열과 PE 형식 고정 실행 파일까지 검사.
- 검증 범위(Windows 11 x64, ARM64 제외): 엔진 시험 1212개, 코어 시험, 엔진 pipe 서버 시험, TSF 종단 시험 16개 시나리오를 TSF RichEdit·EDIT(IMM 연결)·IMM 직접 처리 창 × 실제 키 입력, 64비트·32비트 DLL에서 통과. 샌드박스: 실제 AppContainer·LPAC·낮은 무결성 자식 프로세스로 엔진 파이프 접속·요청 제한·가로채기 거부 시험(`windows/tests/sandbox_pipe.cpp`)과, AppContainer 안에서 돌린 TSF 종단 시험(TSF RichEdit, 64비트·32비트 DLL, 16개 시나리오, 엔진 후보 포함) 통과. 엔진이 없을 때 샌드박스 입력기는 엔진을 띄우지 않고 경량 엔진을 쓴다. 경량 모델(`nikl-morph.hspm`)과 배포 승인된 경계 보정 모델(`boundary-refiner.npz`, SHA-256 91c644bb…)을 포함한다.
