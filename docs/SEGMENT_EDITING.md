# 수동 분절 편집

자동 결과가 붙거나 나뉜 위치를 잘못 고르면 변환 상태에서 직접 고칩니다. 자동 띄어쓰기
모델의 실험·학습 결과와 무관하게 Rust 입력 세션과 macOS 표시 계층에서 동작합니다.

| 동작 | 조작 |
|---|---|
| 어절 선택 | ← / →, 선택 어절을 조합문 안에서 강조 |
| 오른쪽 경계를 한 글자 줄이기 | Shift+← (후보 창 아래 줄의 줄이기도 같음) |
| 오른쪽 경계를 한 글자 늘리기 | Shift+→ (늘리기도 같음). 다음 어절을 다 가져오면 두 어절이 합쳐진다 |
| 앞 어절과 합치기 | ←로 앞 어절을 고른 뒤 Shift+→ |
| 확정 | Enter, 계속 입력, 기존 포커스 이동 확정 경로 |
| 취소 | Esc로 원문 복원. 후보를 고르는 중이면 Esc로 후보 선택을 먼저 취소 |
| 수동 경계를 고친 뒤 또는 재편집 중 끝 글자 삭제 | Backspace, 현재 경계를 유지하며 grapheme 하나 삭제 |
| 확정된 문장 다시 편집 | 텍스트 선택 후 Control+Shift+R 또는 입력 메뉴 |

마지막 어절을 줄이면 떼어낸 글자를 새 어절로 만듭니다. 다음 어절이 이미 있으면 그 앞에
붙입니다. 늘리기는 다음 어절의 첫 글자를 가져오고, 남은 글자가 없으면 두 어절을 합칩니다.
macOS 0.5.3부터 경계 조정은 이 두 키로만 한다. 다른 단축키와 겹칠 수 있는 합치기 전용 키를 두지 않고,
후보 창의 「앞과 합치기」「뒤와 합치기」 단추도 없앴다. 코어의 `HC_KEY_MERGE_PREVIOUS`·`HC_KEY_MERGE_NEXT`는
C ABI 호환과 Windows 후보 창 때문에 남겨 둔다.
한 글자는 Unicode extended grapheme cluster입니다. 한글 분해 자모, 결합 악센트,
피부색·ZWJ·국기 이모지를 내부에서 자르지 않습니다.

영향받은 어절의 한자·이모지·로마자 후보는 원형으로 되돌린 뒤 새 경계로 후보를 다시
생성합니다. 다른 어절에서 고른 후보는 유지합니다. 명시적인 연속 공백을 건너서 합치지
않습니다. 변환 상태 밖의 Shift 방향키는 기존처럼 앱에 전달됩니다.

## 확정 텍스트의 재진입

`selectedRange()`와 `string(from:actualRange:)`의 범위 및 반환한 문자열의 UTF-16 길이가
모두 일치할 때만 시작합니다. 빈 선택, NUL, 제어문자·줄바꿈, 1,000 Unicode scalar를 넘는
선택은 거부합니다. 자동 띄어쓰기 엔진을 호출하지 않으며 사용자가 선택한 문자열만 읽습니다.
접근성 권한이나 클립보드는 사용하지 않습니다.

최초 `setMarkedText`는 문서 기준 선택 범위를 교체합니다. 이후 길이가 달라져도 옛 범위를
재사용하지 않고 현재 marked text를 갱신합니다. Enter는 편집 결과를 확정하고 Esc는 원래
문자열을 복원합니다. 원래 rich-text 속성이나 확정 후 선택 강조 복원은 보장하지 않습니다.
앱이 선택 영역 API를 지원하지 않거나 다른 범위를 돌려주면 단축키를 소비하지 않습니다.

재편집 중이거나 입력한 문장의 경계를 직접 고친 뒤에는 Backspace가 현재 보이는 마지막 글자를
지우며, 최초 원문은 Esc용으로 유지합니다. 전부 지운 뒤에도 Esc로 복원할 수 있습니다.
입력 중이던 문장은 미확정 조합으로 돌아가고, 확정 텍스트의 재편집은 원문을 다시 확정합니다.
현재 marked range의 문서 위치를 기억해 빈 범위에 복원하고, 확정·포커스 이동·reset 후에는
그 위치를 폐기합니다. 빈 상태에서 다시 입력하면 불필요한 공백을 붙이지 않습니다. 직접
고치지 않은 일반 변환의 Backspace는 기존처럼 원문으로 돌아가 마지막 글자를 지웁니다.

## 검증

```bash
cargo test --offline --manifest-path core/Cargo.toml
bash macos/test_segment_editing.sh
```

Rust 테스트는 기존 39개와 새 20개, 총 59개를 포함합니다. 400개 Unicode 조합에서 40번씩 경계를
변경해 문자가 사라지거나 grapheme 내부가 분리되지 않는지 확인합니다. 후보 초기화,
다중 공백 보존, 확정 경로별 자동 엔진 미호출, Esc 원문 복원도 검증합니다.

독립 AppKit harness의 41개 검사는 실제 후보 패널 버튼을 클릭하고 NSTextView에서 선택 영역을 marked
text로 바꾼 뒤 길이가 변하는 확정·취소를 실행해 문서 앞뒤가 보존되는지 확인합니다.
Swift Character/UTF-16 기준 64개 조합을 C ABI 결과와 대조하고 키 이벤트 및 선택 범위
실패 조건을 검사합니다. 패널과 선택 강조의 PNG는 `build/segment-editing/`에 생성합니다.
앱의 `--self-test`에도 동일한 C ABI·키·범위 검사가 포함됩니다.

실제 InputController와 harness가 `MarkedTextState`를 공유하므로 빈 preedit 처리도 같은 코드를
사용합니다. 전체 삭제 후 Esc·Enter·포커스 이동·reset·새 입력을 각각 검증하고, 클라이언트의
커서 위치가 달라져도 취소는 원래 빈 범위에 복원되는지, 이후 새 조합은 이전 위치에 끌려가지
않는지 확인합니다.

이 harness는 IMK 입력기로 등록하지 않습니다. 전체 Swift typecheck와 별개로, 새 버전을
시스템에 설치한 뒤 실제 TextEdit·브라우저 등 각 앱의 IMK 경로에서 동작하는지는 미검증입니다.
